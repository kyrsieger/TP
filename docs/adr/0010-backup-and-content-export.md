# 统一导出包用于浏览与导入

TP 只提供“导出”和“导入”两个入口，统一导出全部历史记录、整理信息和应用附件。同一个 ZIP 包包含 HTML 目录、records.json 和附件，既可在外部查看和处理，也可直接导入 TP；不再区分备份包和内容导出包，也不再使用 manifest.json 或 JSON 中的 format 字段，保留 version 进行数据版本校验，以避免用户选择用途时重复导出相同数据。导出包不包含应用设置，文字保留完整原文。

导出 ZIP 文件名使用本机当地时间的年月日时分秒，例如 tp-export-20261028-204911.zip。

导出只打包 TP 已持有的附件，不额外读取路径引用指向的用户原文件；路径引用保留原路径，并列明未包含文件本体的记录及换机后可能不可用的限制。此选择延续 TP 对用户原文件与应用附件的所有权边界，接受导出包不能保证所有文件记录脱离原机器使用的限制，以免一次导出意外读取大量外部文件。

导出使用不加密的 ZIP，保存前明确说明未加密。导入采用替换现有记录与分组的方式，确认弹窗明确提示替换不可撤销，不自动备份当前数据。相比合并导入，此方式使导入结果可预测，也避免在本次功能中引入重复记录及同名分组的合并语义。

导出始终排除当前带敏感到期标记的记录，不提供包含选项；此边界依赖现有标记，不能保证识别所有敏感文本或曾经敏感的记录。导入保留原时间和清理规则，确认页告知预计立即清理的数量，并提供保留这些记录的选择；选择保留时，只将原本会被清理的记录最后使用时间改为当前时间，保留原创建时间。

导入时若普通记录数量超过当前保留上限，则自动将数量上限改为导入后普通记录数量加 100，未超限时不调低原上限；不再使用原有的 500 条固定限制。此调整始终执行，与是否保留时间过期记录的选项无关，以优先保留导入的数据，同时不通过分组改变记录的整理结果。时间过期记录仍由用户选择按原规则清理或更新最后使用时间后保留。

已有附件缺失时保留记录及可用信息，并沿用现有的可用性判断与展示：文件记录依赖的文件已不存在时显示“文件已不可用”，已有视频首帧或缩略图仍可显示，但不代表文件本体可用。导出不因这种既有缺失而丢弃整条记录。

导入会替换数据库记录和独立存放的附件，因此以操作锁排除后台采集、附件生成与数据修改，并在替换前完成包校验。仅用于失败或中断回退、成功后删除的内部恢复日志、原数据库临时副本与同事务提交标记共同区分已提交和未提交的恢复，启动时完成清理或回退，避免只靠一次数据库事务掩盖附件替换失败；若运行中的附件回退失败，暂停后续数据操作，等待重启恢复，防止继续写入的数据随后被回退覆盖。
