# 大图预览由原生窗口绘制，持续更新同一个缩放目标

大图预览要求图片与窗口一起缩放；WebView 重绘与系统窗口位置、尺寸更新不能同步完成，曾导致背景露出、白黑帧及鼠标锚点附近的标记跳动。逐次截图覆盖重绘过程虽然减少了闪动，却引入串行等待，使连续滚轮输入出现明显停顿，因此采用原生图片绘制：Windows 保留原图缓冲，通过 `UpdateLayeredWindow` 同时提交画面、位置和尺寸；macOS 使用 AppKit 窗口与保留的图像视图，共享缩放几何计算，输入持续更新同一个目标，画面趋近最新目标而不排队完成每次滚轮动画。

完整图片几何与实际可见窗口分开计算：允许图片放大到超过屏幕，但只在当前屏幕可用工作区内显示，保留 Windows 任务栏及 macOS Dock、菜单栏；缩放锚点和拖动始终依据完整图片几何，避免裁剪改变图片位置。代价是需要维护两个平台的绘制、输入和控件实现；网页图片缩放库无法负责桌面窗口合成，因此不保留旧网页大图预览作为第二套实现，小预览继续使用 WebView。

该选择经过 Windows 独立原型的连续滚轮操作和桌面录像验证，用户确认手感后批准正式接入；原型验证不等同于正式实现或全部设备配置的验收，macOS 尚未经实机验证。实验录像、临时检查工程和失败方案的逐次记录不作为长期架构文档保留。
